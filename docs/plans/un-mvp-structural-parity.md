# Plan: un-MVP → full structural parity with retail

**Status:** active strategy as of 2026-05-31. Supersedes the ad-hoc
"MVP/de-MVP" comments scattered through `src/`.

## Principle

The goal is a **complete structural port** that mirrors retail's function
decomposition and control flow. MVPs, simplified state machines, hardcoded
"synthetic data" tables, and `--force-*` injections are **sanity-test
scaffolding only** — a way to see pixels/behaviour early and prove a leaf works.
They are **PORT DEBT**, never destinations. We retire them by porting the real
structure and validating each node against retail.

Why now (not "after playable"): MVP shortcuts become load-bearing as other code
depends on them, so the migration cost compounds. And synthetic-data stubs are
easy to lose track of — they silently cap parity. The trigger case is
engine-quirks **§69**: the simplified `scene1_player_ctrl` (raw `atan2(dpad)`
impulse) cannot reproduce retail's controller, so the table-corner divergence has
to be chased piecemeal on a skeleton that doesn't match retail. A faithful
`FUN_0048670f` port makes that behaviour fall out for free.

## Two kinds of debt — only one is currently tracked

1. **Unported functions** — already tracked by the **port-ledger**
   (`tools/gen_port_ledger.py` → `docs/port-ledger.{md,json}`, `STATUS.md`;
   regenerated by the `tools/git-hooks/pre-commit` hook). Status set:
   verified / stubbed (`CALL_TRACE_ENTER_STUB`) / ported / unported.

2. **MVP shortcuts INSIDE "ported" code** — *not tracked anywhere*. These are the
   simplifications, hardcoded tables, and synthetic data that make a function
   "ported" in the ledger while still diverging structurally from retail. This is
   the gap the un-MVP must close first, so nothing gets lost. Examples found in a
   2026-05-31 sweep (inconsistent markers: `MVP`, `de-MVP`, `hardcode`,
   `deferred`, `scaffold`):
   - `scene1_player_ctrl.c` — hand-rolled controller standing in for the
     `FUN_0048670f` cc08 state machine (the §69 root cause).
   - `collision_house.c` `k_house_objects[]` — hardcoded new-game-tier-0 furniture
     table; the real `FUN_0044c88f` / `FUN_00436f97` stage-position writer is
     unported.
   - `scene1_postload.c` — `--force-walker-phase2` injection + flag-gated camera
     groundtruth standing in for real save-state sourcing.
   - `scene1_pass_f.c` — ports only Pass F of `FUN_004161c7`, not the A–E context.
   - `scene_map_meshes.h` / `scene.c` — hardcoded stage index 0 / save-slot until
     the save-slot UI lands.

## Step 1 — make the debt visible (do this FIRST, it's cheap)

A single grep-able tag + a generated registry, mirroring the port-ledger.

**Tag convention** (one canonical marker, replaces MVP/de-MVP/hardcode/etc. in
comments going forward):

```c
/* PORT-DEBT(<kind>, <engine-fn-or-NONE>): <one-line what's synthetic + retire condition> */
```

`<kind>` ∈ `stub` | `synthetic-data` | `simplified` | `hardcode` | `scaffold` |
`force-flag`. The middle field names the real engine function that retires it
(or `NONE` if it's pure scaffolding). Example:

```c
/* PORT-DEBT(simplified, FUN_0048670f): raw atan2(dpad) impulse; real controller
   is the cc08 state machine w/ db05c sticky-diagonal facing. Retire = §69. */
```

**Registry:** `tools/gen_port_debt.py` scans `src/` for `PORT-DEBT(...)` →
`docs/port-debt.md` (table grouped by kind + retiring engine-fn) and
`docs/port-debt.json`. Wire into `tools/git-hooks/pre-commit` next to the
port-ledger regen so it can never go stale. Headline count goes into `STATUS.md`.

**Migration of existing markers:** one pass converting the current scattered
`MVP`/`de-MVP`/`hardcode`/`deferred`/`scaffold` comments to `PORT-DEBT(...)`.
`CALL_TRACE_ENTER_STUB` stays as-is (it's the runtime-wired-stub signal and feeds
the port-ledger); a stub may carry both.

## Step 2 — structural migration of the control SPINE (node-by-node)

The leaf ports (render quad, mesh/xfile, tables, audio, collision math) are
largely faithful — leave them. The debt is the **stateful per-frame spine**: the
hand-assembled `scene1_*_tick` driver approximating
`FUN_00442cef → FUN_0048670f → FUN_0048b850 → FUN_00483170/FUN_0048cdcc`, plus
the simplified state machines inside it.

**Method per node** (this is the whole loop):
1. Pick one scaffolding node; read its real `FUN_xxx` decomp end-to-end.
2. Port it as a **faithful translation** (same control flow, same globals, same
   sub-call structure) — replacing the MVP node, not patching it.
3. **Validate via the existing Frida hook-and-diff harness** (E.1/E.2): hook the
   same VA in retail, diff args/retval/state-writes per frame. Add a
   `CALL_TRACE_ENTER` probe → promotes it to "verified" in the ledger.
4. **Regression-guard** with the scenario benches (`house-walk-*`,
   `house-table-corner`, per-frame `wall_collide_diff`) — must not regress the
   currently-bit-identical frames or the W3 cardinal walks.
5. Retire the corresponding `PORT-DEBT(...)` tag(s) in the same commit.

Far-future cc08 states (combat/dungeon/event branches not on the near path) may
stay as **structurally-shaped stubs** (real signature + `CALL_TRACE_ENTER_STUB`,
empty body) so the skeleton matches even before the body lands.

## Step 3 — sequencing

Spine-first, in dependency order, each node retiring concrete debt:

1. **`FUN_0048670f` (cc08 player/actor controller)** — FIRST. It's the active
   front (STATUS top-chip), it's the §69 root cause, and converting it fixes the
   table-corner divergence for free. Port the cc08==1 free-roam path + the
   transition states on the critical path; stub the rest structurally. Replaces
   `scene1_player_ctrl`'s `atan2` model with the real `db05c` facing update.
2. **`FUN_0048b850` (Cpop) + `FUN_0048cdcc`** — the controller's movement/impulse
   + event sub-machine it already calls into (partially mapped this session).
3. **`FUN_00442cef` per-frame INGAME dispatch** — make the `scene1_*_tick` wiring
   a faithful translation of the engine's update order, not a hand-tuned mimic.
4. **Furniture/stage placement** — port `FUN_0044c88f`/`FUN_00436f97` (the
   `DAT_0438c058` stage-position writer) to retire `collision_house.c`'s hardcoded
   `k_house_objects[]` and generalise past new-game tier 0.
5. **Save-state sourcing** — retire `--force-walker-phase2` / hardcoded stage/slot
   once the real save-slot path lands.

Re-derive ordering from `docs/port-debt.md` (the registry, once it exists) +
`STATUS.md` blocker as each node lands.

**Controller un-MVP — chip breakdown (Steps 3.1 + 3.2 expanded, 2026-05-31).**
The full structural map of the in-game controller is engine-quirks **§75**: the
tick is a 3-function pipeline (`FUN_0048670f` cc08 dispatch → `FUN_0048b850`
movement/effects → `FUN_00483170` collision, already ported), and the HOUSE
free-roam walk is split across all three. **Key correction:** the walk impulse
(`daabc += sin(db05c)·0.1`) lives in `FUN_0048670f`'s **cc08==1 controllable
code** (written as `*(player+0x904)`, §61), **not** in `FUN_0048b850` (whose only
sin/cos accumulate is the `da1bc`-gated stun/hop path, accel 0.3, dead in
free-roam) — so §69's "impulse at FUN_0048b850 L319-326" was imprecise. Chips
(bottom-up, each bit-exact on `house-walk-*`/`house-table-corner`/`wall_collide_diff`,
each adds only *structural stubs* never new *simplified* bodies):

1. **Chip 1** — `FUN_0048b850` free-roam body: speed-cap+clamp(0.175),
   facing octant `dab00`+sticky, call `collision_resolve_player`, damp tree
   (→0.82 grounded); dash/egg/`da1bc`/cutscene branches structurally
   gated-off. Tick calls it instead of doing clamp/octant/collision/damp inline.
2. **Chip 2** — `FUN_0048b850` render-slot populator (`DAT_056dacc0` fill via the
   `FUN_0044376a` record copy) → retires `PORT-DEBT(synthetic-data, FUN_0048b850)`
   (`scene1_chr_walker.c:84`).
3. **Chip 3** — `FUN_0048670f` prologue + per-frame bookkeeping + tail shell
   (actor refresh, transition-flag fades, `b74c/750/924/b4e0` counters,
   `FUN_00486435` tail clamp). cc08 dispatch shell routes cc08==1 to the free-roam
   body. No behaviour change.
4. **Chip 4** — `FUN_0048670f` cc08 dispatch + cc08==1 arm faithfully (the
   **step-1 walk impulse** lives here), off-path states as
   `CALL_TRACE_ENTER_STUB`; deletes the hand-rolled tick → retires
   `PORT-DEBT(simplified, FUN_0048670f)`. Add `CALL_TRACE_ENTER(0x48670f)` +
   Frida hook-and-diff → "verified".
5. **Chip 5+** — flesh out gameplay cc08 states (shop counter, dialogue, menus)
   as each becomes reachable; each replaces a stub, adds no debt.

## Definition of done (per node)

- Real `FUN_xxx` faithfully ported (control flow + globals + sub-calls match).
- `CALL_TRACE_ENTER` probe added; hook-and-diff vs retail clean → "verified".
- Regression benches still pass (no parity regression on prior-matched frames).
- All `PORT-DEBT(...)` tags it subsumes removed in the same commit.

## Done when

`docs/port-debt.json` is empty (every synthetic stub retired) and the in-game
spine functions are all "verified" in the port-ledger. At that point the
retail-accurate constant/leaf-math tuning happens on a faithful skeleton, where a
divergence means a real bug — not a missing structure.
